# LICENSING AND PROVENANCE

## Core law

Public availability is not license permission.

Lucien must preserve source identity, version context, attribution requirements, and license state through acquisition, summarization, comparison, and promotion.

## License states

- KNOWN_PERMISSIVE — license has been identified and permits relevant reuse subject to its terms.
- KNOWN_RESTRICTED — license is known and restricts the intended reuse.
- PUBLIC_REFERENCE_ONLY — source may be publicly inspected/referenced, but reuse/copying authority is absent or intentionally limited.
- UNKNOWN — license or reuse permission has not been established.

UNKNOWN means REFERENCE ONLY until resolved.

## Default content storage policy

Lucien normally stores:

- provenance and source identity;
- metadata;
- canonical links;
- versions, tags, releases, commit SHAs, dates, and hashes when relevant;
- bounded quotations when legally and technically appropriate;
- summaries;
- extracted observations;
- structural notes;
- comparison notes.

Lucien does not default to storing complete third-party articles, proprietary documentation, design packs, component libraries, templates, themes, screenshot collections, or other copyrighted resources.

## Explicit prohibitions

Do not:

- strip attribution;
- imply external work was authored by Lucien;
- remove source/version identity during summarization;
- copy restricted or proprietary design packs into Git without explicit authority;
- copy large copyrighted resources merely because they are viewable online;
- treat a public Git repository as automatically permissively licensed;
- vendor source code as part of a knowledge-acquisition lane.

## Vendoring boundary

If permissively licensed source code is intentionally vendored later, that requires a separately authorized work package that records exact source/version, preserved license/notice obligations, modification status, and purpose.

## Provenance minimum

Every source record must capture canonical source identity, provider, retrieval date, source type, authority reason, license state, status, and available version/date/SHA information. Every promoted knowledge record must remain traceable to source and observation IDs.
