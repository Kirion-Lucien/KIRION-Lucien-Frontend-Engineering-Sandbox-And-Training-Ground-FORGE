## A. Modal versus nonmodal; native versus design system

O07 differentiates HTML dialog.show() nonmodal, showModal() modal/top layer and open attribute; O08 and O12 describe native document blocking and inertness. APG O13 describes truthful ARIA modal semantics; USWDS O19 and Primer Product O25 describe transient/interruption/confirmation use. These **align only at the interaction-intent level**. Role, CSS backdrop or a visually floating component does not establish native showModal(), top-layer document blocking or inertness. Pinned Primer base Overlay O34 defaults to role none, reinforcing that it is not equivalent to native dialog. No specific app uses any of these mechanisms in this corpus.

Countercontexts matter: USWDS O19 recommends inline errors, ordinary page alerts/status and dedicated pages for complicated multistep work; Primer O25 asks whether extra-large Dialog should instead be a page. APG disclosure O18 and WHATWG popover O11 are distinct nonmodal presentation possibilities, not replacements for every important modal. The absent APG standalone nonmodal page supplies no additional evidence. No universal chooser is inferred.

## B. Modal focus, semantics, inertness and naming

WCAG O01 requires keyboard operability with the actual underlying path-dependent exception. O02 requires keyboard-only exit from focused components and instructions for nonstandard exit: it does not prohibit a modal Tab loop when keyboard exit remains possible. O03 concerns meaning-preserving focus order under its sequencing condition; O04 visible keyboard focus; O05 prohibits **entire** author-content obscuration under its exceptions and user-opened reveal note, not every partial overlap. None specifies a mandatory focus-hook implementation, first control or close-button location.

APG modal O14 recommends focus inside, wrapped Tab/Shift+Tab and Escape closing; USWDS O22 advises testing containment but offers no Kirion test result. WHATWG O08/O12 normative inertness is distinct from APG O13 truthful aria-modal semantics and pinned Primer O31 root ARIA attributes. Calling an imported useFocusTrap in pinned O32 does not establish runtime containment or inertness, and pinned O34 role none does not become an accessible dialog automatically.

Initial focus varies. WHATWG O09 has autofocus/focus-delegate steps with guard/no-op conditions. APG O15 discusses focusing static top content for complex text/scroll, least destructive actions for hard-to-reverse tasks and common actions for simple cases. Primer Product O26 documents initialFocusRef/footer autoFocus; pinned O32 passes refs to **uninspected** hooks. Together they offer contextual options, not a universal first-input or destructive-action rule. Return-focus advice O16 allows missing-invoker and logical next-step exceptions; WHATWG O09 is conditional, and Primer O26/O32 source ref presence does not prove restoration.

Accessible name and description: APG O13 and USWDS O21 emphasize a purpose-identifying heading and optional brief description; APG O15 explicitly advises against flattening long structured content. Primer Product O26 documents title/subtitle. Pinned code O31 renders root aria-labelledby and **always** aria-describedby while DefaultHeader renders the subtitle target **conditionally**; this poses a possible dangling-ID risk when subtitle is absent, but without rendered DOM/AT testing **is not a demonstrated accessibility failure**. Custom header renderers can change targets. Product documentation text may describe a different release. USWDS O22 visually places X top-right while recommending source-order-last; coupled with O03/O16, this remains system-specific rather than a universal DOM-order rule.

## C. Escape, backdrop, light dismiss and force-action

WHATWG O10 describes native requestClose(), preventable cancel event, closedby states and conditional light dismiss (only topmost eligible dialog, proper trusted pointer endpoint conditions). USWDS O20 describes a **bounded** forced acknowledgment variant with data-force-action and not universally closing. Primer code O32 invokes onClose('escape') after guarded backdrop click (matching target plus preceding mousedown) or Escape; a callback does not itself unmount the dialog. Primer Popover O36 likewise delegates click behavior and does not automatically set open=false.

A consequential contextual tension persists: APG O14 uses Escape for its normal modal pattern while USWDS O20 may suppress conventional dismissal for explicit required acknowledgment. This is **not a proven same-context direct conflict**, but O02 keyboard exit and task/user risk still need to be satisfied. Whether a particular forced gate permits valid keyboard reject/continue/exit remains unknown. APG O15 varies initial action focus by reversibility; APG O16, USWDS O22 and Primer Product O26 describe ordinary visible closers with different contexts. Native cancelable requests, forced variants and library callbacks are not one universal close protocol.

## D. Tooltip, popover and disclosure

WCAG O06 requires qualifying hover/focus-triggered added content to be dismissible (with named exceptions), hoverable where pointer-hover triggered, and persistent under its conditions; it does **not** universally mandate Escape, and unmodified user-agent UI has an exception. APG tooltip O17 provisionally describes trigger-retained focus, role tooltip, aria-describedby, hover and Escape, but **lacks APG consensus**. Primer Product O27 warns important information should not rely on initially hidden tooltip; O28 documents distinct label/description modes, directions and configurable delays without measured AT output. These are different authority classes, not independent runtime agreement.

Pinned Primer Tooltip v1 O35 has @deprecated at the immutable source revision, role tooltip and aria-label/context ID. That does not mean contemporary Primer Product Tooltip O27/O28 is deprecated or that its trigger relationship matches APG O17. The revision/trigger hook context was not established.

WHATWG O11 native popover=auto/manual/hint and conditional light dismiss is **not** automatically Primer Product Popover O29 open/caret/relative/callback behavior or pinned O36 open/context attrs and imported click/Escape hooks. The pinned Escape callback is gated on open; its outside-click hook invocation is not visibly open-gated, and neither automatically mutates owner state. APG disclosure O18 is a different Enter/Space plus aria-expanded button model with optional aria-controls; not a modal/popover protocol simply because content appears.

## E. Responsive, scroll, visual versus DOM order and nested overlays

USWDS O23 warns long modal content may push actions below viewport, suggests scroll cues or a page, and cautions about nested form/accordion context on mobile. Primer Product O25 documents responsive side/bottom-sheet examples and size variants (not actual measured outcomes). Product private Overlay O30 documents responsive composition; pinned O34 supplies Portal by default with **two-condition bypass** (private prop AND feature flag), conditional animation/height/positioning, not browser top-layer proof. Product Tooltip O28 describes placement/delay, not rendered viewport or zoom performance.

O03 meaningful sequential focus order and O05 focus-not-entirely-obscured criterion might apply to an app, but O15/O22/O23/O25/O28/O34 do not supply keyboard recordings, visual overlap measurements, nested top-layer state, scroll/zoom results or AT reading order. Initial focus O09/O15 can affect long-content position. No universal pixel breakpoint, size or nested-overlay implementation is selected.
