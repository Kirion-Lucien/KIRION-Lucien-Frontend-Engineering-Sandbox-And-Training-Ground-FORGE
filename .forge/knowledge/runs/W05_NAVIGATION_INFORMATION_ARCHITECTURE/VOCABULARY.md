# W05 NAVIGATION / INFORMATION ARCHITECTURE VOCABULARY

**40 working definitions.** Evidence linked through W05 observation IDs; WAI/GOV.UK/USWDS/Primer system-specific terms are not universal law. WCAG definitions apply only within exact normative SC scope. These terms are analytic working language pending Maintainer review.

### information architecture

**Working definition:** Organization and relationships of information, destinations and user tasks.

**Evidence:** W05-O16, W05-O26, W05-O30. **Boundary:** Source-specific context; not an implementation requirement.

### navigation architecture

**Working definition:** Organization of ways to move among destinations and their scopes.

**Evidence:** W05-O16, W05-O24, W05-O30. **Boundary:** Source-specific context; not an implementation requirement.

### global navigation

**Working definition:** Cross-site or cross-product routes to major areas.

**Evidence:** W05-O16, W05-O24, W05-O25. **Boundary:** Source-specific context; not an implementation requirement.

### primary navigation

**Working definition:** Most prominent set of top-level destinations in a specific context.

**Evidence:** W05-O16, W05-O24. **Boundary:** Source-specific context; not an implementation requirement.

### secondary navigation

**Working definition:** Supporting links or next-level routes within or adjacent to primary navigation.

**Evidence:** W05-O16, W05-O24, W05-O26. **Boundary:** Source-specific context; not an implementation requirement.

### local navigation

**Working definition:** Routes for the current area/section, rather than the whole site.

**Evidence:** W05-O26, W05-O31. **Boundary:** Source-specific context; not an implementation requirement.

### contextual navigation

**Working definition:** Routes relevant to the current object/task and its neighboring destinations.

**Evidence:** W05-O30, W05-O31, W05-O33. **Boundary:** Source-specific context; not an implementation requirement.

### utility navigation

**Working definition:** Links to auxiliary destinations such as sign-in/help rather than primary content hierarchy.

**Evidence:** W05-O16, W05-O24. **Boundary:** Source-specific context; not an implementation requirement.

### navigation landmark

**Working definition:** Programmatically identifiable navigation region, optionally named to distinguish multiple instances.

**Evidence:** W05-O14, W05-O35. **Boundary:** Source-specific context; not an implementation requirement.

### skip navigation

**Working definition:** Mechanism for bypassing repeated content to reach primary content.

**Evidence:** W05-O01, W05-O22. **Boundary:** Source-specific context; not an implementation requirement.

### hierarchy

## Non-equivalences

- **Navigation ≠ action:** A link moving to a destination and a button running a task command communicate different semantics (W05-O11/O13/O33/O38). Disclosure expansion is another interaction, not automatically site navigation.
- **Hierarchy ≠ history:** Parent/ancestor links express information structure; browser back follows visit history (W05-O19/O28/O32).
- **Breadcrumb ≠ stepper:** Transaction stages are a linear task relationship, not necessarily an information hierarchy (W05-O17/O19/O28).
- **URL-backed tabs ≠ in-page tab panels:** Primer UnderlineNav navigates dedicated linked views while GOV.UK tabs show sections of the current page (W05-O21/O33).
- **Site navigation ≠ application menu:** WAI application menus use specialized roles and keyboard behavior beyond ordinary nav links (W05-O11/O13).
- **Visual active state ≠ sufficient programmatic current state:** aria-current and appropriate accessible naming must be evaluated in real pages (W05-O12/O18/O35/O37).

## Explicit unknowns

No universal hierarchy depth, sitemap model, accepted menu library/router, outcome-tested label taxonomy, or project-specific route structure. A URI-backed view does not require a particular frontend routing stack.
